# Тестирование

## 1. Что проверяется

- Собирается ли `index.html`.
- Нет ли ошибок JS/консоли.
- Совпадают ли данные графиков с расчётным массивом.
- Рабочая точка лежит на кривой момента и на линии нагрузки.
- `I`, `cosφ`, `η`, `P₂` при 100 % близки к паспорту/типовым данным.
- Монотонность `I`, `U`, `n`, `s`, `P₁`, `P₂` по нагрузке.
- `η(0) = 0`, `P₂(0) = 0`, `cosφ(0)` низкий.
- Стартовый/максимальный момент и ток.
- Переходные процессы: `tStart`, пики, первые значения `U/I/M`, совпадение live и таблицы.
- Способы пуска, наложение, однофазный режим.
- Тур, подсказки, темы, XLSX/CSV, проект, отчёт, зум/PNG, мобильный drawer.

Не проверяется автоматически:

- точное совпадение с паспортными испытаниями конкретного двигателя;
- реальные время-токовые кривые и селективность по каталогам;
- расчёт КЗ по схеме сети;
- визуальный дизайн на всех разрешениях (только выборочные скриншоты).

## 2. Запуск

```bash
npm ci
npm test
```

Или по частям:

```bash
npm run test:smoke
npm run test:static
npm run test:transient
npm run test:features
```

Браузер:

```bash
CHROME_PATH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" npm test
```

В CI — `browser-actions/setup-chrome`.

Допуски:

- `P₂(100)` — 2 %;
- `I(100)` — не выше `Iн · 1,06`;
- `n(100)` — не ниже `0,99·nн`;
- `η`, `cosφ` — 2 %;
- рабочая точка vs sweep — 1,5 % по току, 0,2 % по n/U;
- момент: старт/максимум — 2 %, рабочая точка — 0,5 %.

Дополнительно:

- данные `iu/speed/eff/power` совпадают с `rep.sweep` (1e-9);
- `M(n)` — 241 точка, старт = `Mп·u²`, максимум = `Mmax·u²`;
- `η(0) < 1 %`;
- `cable.loaded` = 2 для 1 фазы, 3 для 3 фаз;
- `breaker.poles` = 1/3;
- нет `NaN`/`Infinity`.

## 5. Переходные процессы

Базовый сценарий: 3ф 15 кВт, 4п, 380 В, постоянный момент 75 %, `Jнагр = 0,3`, 50 м.

Дополнительно `tests/engine.mjs` проверяет ядро без браузера: I, n, Mн, Mп, Mmax, момент, constpower, потери, кабель, 1ф 11, коэффициент соединения Y/Δ и пересчёт момента.

| Способ | tStart | Пик I | Пик M | Первое U |
|---|---:|---:|---:|---:|
| DOL | 0,89 с | 195 А (6,6×) | 216 Н·м | 95 % |
| Y–Δ | 2,95 с | 195 А (6,6×) | 216 Н·м | 56 % |
| Софтстартер, 4,5× | 5,82 с | 132 А (4,5×) | 206 Н·м | 30 % |
| ПЧ | 5,68 с | 29 А (1,0×) | 98 Н·м | 4 % |
| Автотрансформатор | 2,89 с | 195 А (6,6×) | 216 Н·м | 63 % |

- Live `tStart` и `peakI/peakT` совпадают с таблицей (допуск 0,25 с / 2 %).
- Y–Δ и AT: пик 195/216 — это бросок при переключении в 2 с; первый ток ниже (115/129 А). Для нагрузки 75 % постоянного момента момент в звезде 68 Н·м < 73,6 Н·м, поэтому звезда сама не разгоняет; это ожидаемо.
- Софтстартер при **3×Iн** и 75 % постоянного момента честно не разгоняет: 88 А (3,0×), момент 40 Н·м < 73,6 Н·м. При 4,5× — разгоняется. Это проверяется вручную/отдельным сценарием.
- Наложение DOL + ПЧ: первичный 1470 об/мин, призрачный 1464, `tStart` 5,68.

Однофазный 5,5 кВт, 230 В, постоянный 75 %, 30 м, софтстартер 4×:

| Способ | tStart | Пик I | Пик M |
|---|---:|---:|---:|
| DOL | 2,03 с | 145 А | 77 Н·м |
| Софтстартер | 6,84 с | 109 А (3,5×) | 77 Н·м |
| ПЧ | 5,68 с | 32 А | 41 Н·м |

## 6. Функциональные тесты

- Тур: автозапуск, 8 шагов, «Пропустить», ключ `motor-tour-v1`.
- Подсказка J нагрузки: текст, иконка, мобильный tap.
- XLSX: скачивание, ZIP-сигнатура, листы.
- CSV: заголовок и строки.
- Проект: сохранение JSON, загрузка, восстановление состояния.
- Отчёт: 5 изображений графиков.
- 1 фаза: `loaded = 2`, автомат 1P, Y–Δ/AT отключены.
- Темы: `html[data-theme]`.
- Зум: колесо меняет `view`, сброс обнуляет, PNG валиден.
- Мобильный drawer: открывается, параметры доступны.
- Реальный проект `tests/fixtures/constpower-y-6p.json` (constpower 95 %, Y/380, 6 полюсов, 30 А):
  - предупреждение «Постоянная мощность»;
  - предупреждение «380/660 → нужна Δ»;
  - предупреждение о несовпадении 4p каталожного типа и 6p расчёта;
  - рекомендация «разгрузка/сцепление/ПЧ с разгрузкой»;
  - все 5 способов пуска — «не выходит на скорость».

## 7a. Глубокий прогон и эталоны

`tests/deep.mjs` — единственный тест, который проверяет приложение **целиком**,
а не по кускам:

- **комбинаторный прогон** — 3 и 1 фаза × 4 режима × 5 способов пуска × MCB/MCCB;
  на каждой комбинации: нет NaN/`undefined` в `rep` и в DOM, графики с данными,
  номинал автомата ≥ рабочего тока, кабель держит ток, бейдж способа пуска
  совпадает с состоянием;
- **инварианты** — ток растёт с мощностью, ΔU растёт с длиной, сечение не
  уменьшается с ростом линии, просадка при пуске выше рабочей, температура
  растёт с нагрузкой, время до предела падает, 1 фаза: I = P₁/(U·cosφ);
- **ВТХ** — отсечка/селективность/Icu согласованы с числами, таблица данных есть; проверка пуска по тепловой зоне (бейдж, замечание, предупреждение, строка в «Проверке условий»), реакция времени разгона на «J нагрузки» (кэш сравнения) и эквивалентный ток при повторных пусках;
- **экспорты** — PNG (сигнатура и размер), CSV (строки/колонки, без NaN),
  XLSX (zip, листы), отчёт (5 графиков, таблицы, заголовок, `print`);
- **персистентность** — state после перезагрузки, проект save/open, варианты,
  share-ссылка, битый проект;
- **границы** — клампы ввода, нулевая мощность, минимальная длина, мусор
  в кривой M(n), постоянная мощность без разгона, работа без `localStorage`;
- **интерфейс** — 5 вкладок, подсказки по наведению, тур, зум/сброс графиков,
  мобильная панель;
- **производительность** — медиана/максимум пересчёта, число узлов DOM, загрузка;
- **эталоны** — 15 состояний сравниваются с `tests/fixtures/deep-baseline.json`
  (расхождение = изменение расчёта; обновляйте осознанно: `--baseline`).

Если эталон поменялся сам собой — это регресс: смотрите `docs/MODEL.md` и
`git diff tests/fixtures/deep-baseline.json`.

## 7. Ручная проверка перед релизом

1. `npm run build`, `npm test`.
2. Открыть `index.html` (без `?debug=1`).
3. Проверить тур при первом запуске (очистить `motor-tour-v1`).
4. Пройти все вкладки, темы, 1/3 фазы.
5. Проверить графики: M(n), I/U, n/s/f₂, η/cosφ, мощности.
6. Пуск: DOL, Y–Δ, софтстартер, ПЧ, AT; наложение.
7. Отчёт: 5 графиков, печать.
8. XLSX/CSV.
9. Мобильный вид (390×844).
10. Обновить скриншоты, если UI менялся.

## 8. CI

`.github/workflows/ci.yml`:

1. checkout;
2. Node 22 + npm cache;
3. Chrome (`browser-actions/setup-chrome`);
4. `npm ci`;
5. `npm run i18n` + `git diff --exit-code -- src/lang-en.js` — словарь должен быть собран из `src/lang-en/*.js`;
6. `npm run build`;
7. `git diff --exit-code -- index.html` — собранный файл должен совпадать с коммитом;
8. `npm test` с `CHROME_PATH` (первым шагом внутри него — `tools/i18n-audit.cjs`).

Если CI падает на `git diff` — соберите локально (`npm run i18n && npm run build`) и закоммитьте `src/lang-en.js` и `index.html`.

`npm test` начинается со статической проверки словаря: у каждого литерала в
`t()/tf()/tHtml()` должен быть перевод в `src/lang-en.js` (иначе код 1). Это ловит
строки, которые в EN остались бы русскими, но которых нет в браузерных сценариях.

## 9. Как добавить тест

- Статический сценарий — добавьте объект в `scenarios` в `charts-static.mjs`; проверьте ожидаемые значения.
- Переходный — добавьте метод в `charts-transient.mjs`.
- Функциональный — отдельный `test()` в `features.mjs`; не забудьте закрыть контекст/страницу.
- Все тесты должны завершаться `process.exitCode = 1` при ошибке и закрывать браузер.
- Скриншоты — в `test-results/` (gitignored).

## 10. Эталоны и модель

Эталоны получены на модели версии 0.5.0. Если меняются:

- формула Клосса/тока;
- типовые данные;
- кабельные таблицы;
- ограничения софтстартера;
- `cosφ`/`S`/`U` в рабочей точке,

— пересчитайте таблицы выше и обновите тесты.


## ВТХ и тепловой режим

- 6 серий в селекторе, переключение IEK/CHINT/ABB, кривые B/C/D/K/Z и уставки MCCB.
- Точка пуска, кабель, вышестоящая защита, селективность.
- Горячий пуск короче холодного при 150 %; класс 20 удлиняет время до предела.
